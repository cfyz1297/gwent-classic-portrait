# Безопасность

Приложение локальное: веб-слой в WebView, без сервера и без аккаунтов. Ниже — модель
угрозы, что уже сделано, что проверяется автоматически и как сообщить о проблеме.

## Модель угрозы

| Актив | Угроза | Что делаем |
|-------|--------|------------|
| Импортируемый JSON колоды | подмена индексов, `__proto__`, гигантский файл, падение редактора | строгий разбор в `GwentRules.parseDeckJSON`, лимит 64 КБ и 200 записей |
| WebView-страница | XSS через подставленные данные | CSP, `textContent` для имён из данных, никакого `eval` |
| Сеть | подмена/подслушивание, cleartext | HTTPS-only, `usesCleartextTraffic=false`, `allowMixedContent=false` |
| Локальные данные | резервные копии, перенос на другое устройство | `allowBackup=false` |
| Сборка | подмена зависимостей | lock-файл, `npm ci`, аудит в CI |
| Репозиторий | утечка токенов | скан на секреты в тестах и в CI |

Внешний контент ровно один — iframe YouTube для музыки (как в upstream). Без сети
партия играется, музыка не стартует.

## Что ужесточено в этой версии

1. **Импорт колод.** Было: `card_dict[deck.leader].row` падал на любом мусоре,
   `deck.cards` мог быть не массивом, индекс `"__proto__"` проходил дальше.
   Стало: `parseDeckJSON` проверяет форму, числа, диапазоны, фракцию лидера, наличие
   карты в коллекции и лимит копий; ошибки показываются списком, а не роняют приложение.
2. **Файл колоды.** Лимит 64 КБ до чтения, лимит 200 записей.
3. **CSP.** `default-src 'self'`, `object-src 'none'`, `base-uri 'none'`,
   `form-action 'none'`; внешние источники — только YouTube для музыки.
4. **Android.** `allowBackup=false`, `usesCleartextTraffic=false`, единственное
   разрешение — `INTERNET`, провайдер не экспортируется.
5. **Вывод данных.** Имена лидера и соперника из сохранённых данных пишутся через
   `textContent`, а не `innerHTML`.

## Подпись сборок

Все APK подписываются ключом `android/keystore/gwent-debug.keystore` (пароль и алиас
`gwentdebug`), который лежит в репозитории. Это **debug-ключ для личных сборок**:
он нужен только для того, чтобы обновление ставилось поверх предыдущей версии.
Для Google Play и публикации в сторах он не годится — там нужен отдельный
release-ключ, который в репозиторий не попадает.

## Отчёт проверки

| ID | Находка | Серьёзность | Статус |
|----|---------|-------------|--------|
| S-1 | `loadDeck` падал на нечисловом `leader`/`cards` (DoS редактора) | средняя | исправлено |
| S-2 | Индексы карт не проверялись: `"__proto__"`, отрицательные, вне диапазона | средняя | исправлено |
| S-3 | Нет лимита размера импортируемого файла | низкая | исправлено |
| S-4 | `confirm()` с инвертированной логикой в `loadDeck` мог пропустить битую колоду | низкая | исправлено |
| S-5 | Нет CSP в WebView | низкая | исправлено |
| S-6 | `allowBackup=true` и неявный cleartext | низкая | исправлено |
| S-7 | `innerHTML` для имени лидера соперника | низкая | исправлено |
| S-8 | Музыка грузится сторонним скриптом YouTube | принято | ограничено CSP, без сети не влияет |

Отдельная проверка «anti-cheat/DRM» не требуется: приложение не работает с платёжными
или сетевыми сервисами.

## Как проверить самому

```bash
npm ci
npm test                      # 35 тестов, включая security.test.mjs
npm audit --omit=dev --audit-level=high
```

CI (`.github/workflows/android.yml`) дополнительно запускает `gitleaks detect` по
рабочему дереву и собирает APK только после зелёных тестов и аудита.

## Сообщение о проблеме

Откройте issue с меткой `security` или напишите владельцу репозитория. Укажите версию
APK, шаги и, если возможно, минимальный JSON/файл для воспроизведения.
