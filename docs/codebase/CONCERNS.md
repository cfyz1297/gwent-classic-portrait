# Проблемные места кодовой базы

## Обязательные разделы

### 1) Главные риски (по приоритету)

| Важность | Проблема | Доказательство | Влияние | Что сделать |
|----------|----------|----------------|---------|-------------|
| высокая | Нет E2E на устройстве/эмуляторе: всё проверяется в jsdom, который не считает геометрию, тач и жизненный цикл WebView | `tests/helpers/boot.mjs:72-118`; CI только собирает APK и проверяет подпись (`.github/workflows/android.yml:106-139`); Android-тесты — заглушки Capacitor | Регрессии портретной раскладки, жестов и кнопок выходят в релиз незамеченными | Добавить smoke на эмуляторе (установка APK + запуск + скриншот) или ручной чек-лист перед тегом |
| средняя | Повреждённый `localStorage` роняет запуск: `SavedObject` делает `JSON.parse` без `try/catch`, а `Settings` инициализируется статически | `www/gwent.js:3230-3238`, `www/gwent.js:3324-3335` | Любой мусор в `gc-*` ключе (обрыв записи, старая версия) — белый экран до очистки данных приложения | Читать с fallback на значение по умолчанию и удалять битый ключ |
| средняя | Асинхронные эффекты держатся на фиксированных `sleep`, а не на событиях | `www/gwent.js:582` (1000 мс), `1034` (600 мс), `620` (1500 мс); в тестах `sleep` заглушен (`tests/helpers/boot.mjs:109-110`) | На медленном устройстве возможны гонки: тап во время анимации, неверный порядок эффектов; тесты такие случаи не ловят | Переводить критичные цепочки на `await` событий/промисов; для начала — тест с реальными таймерами |
| средняя | Debug-keystore с известным паролем лежит в публичном репозитории | `android/keystore/gwent-debug.keystore`, `android/app/build.gradle:34-42`, `SECURITY.md:34-40` | Кто угодно может собрать APK с той же подписью; для сайдлоада это удобно, для магазина — недопустимо | Оставить, пока сборка только личная; для публикации завести отдельный release-ключ вне репозитория |
| средняя | CSP разрешает `'unsafe-inline'` для скриптов, в `index.html` есть inline-обработчики `onclick` | `www/index.html:14,166-170,186-187` | XSS-поверхность выше, чем могла бы быть; текущий источник данных локальный, поэтому риск ограничен | Убрать inline-обработчики в пользу `addEventListener`, затем убрать `'unsafe-inline'` |
| низкая | Нет линтера, форматтера, typecheck и покрытия; CI проверяет только синтаксис | `.github/workflows/android.yml:32-35`; в корне нет конфигов линтера | Опечатки и мёртвый код ловятся только тестами; стиль файлов уже неоднороден | Добавить ESLint в режиме «только ошибки» и порог покрытия для `rules.js` |
| низкая | Документация местами устарела: README говорит «55 тестов», SECURITY — «35», фактически 59; `package-lock.json` показывает версию 1.1.0 при `package.json` 1.4.1 | `README.md:18`, `SECURITY.md:62`, `package-lock.json:3,9`, `package.json:3` | Читатель доверяет неверным числам; версия в lock сбивает инструменты | Синхронизировать числа при релизе; пересобрать lock (`npm install --package-lock-only`) |

### 2) Технический долг

| Долг | Почему возник | Где | Риск если не трогать | Предлагаемое исправление |
|------|---------------|-----|----------------------|--------------------------|
| Наследованный ландшафтный `style.css` (1570 строк) перекрывается портретным `portrait.css` (2429 строк) | Портретная сборка делалась поверх upstream без удаления старого слоя | `www/style.css`, `www/portrait.css`, `www/index.html:15-16` | Любая правка стилей требует проверки обоих слоёв; мёртвые правила путают | Отдельная задача: удалить/сжать ландшафтный слой с визуальной регрессией (уже отмечено в `docs/ponytail-audit.md:23-26`) |
| Монолитный `gwent.js` (3622 строки): движок, DOM, ИИ, настройки | Наследован от upstream | `www/gwent.js` | Высокий churn, сложные конфликты, невозможно точечно тестировать | Не рефакторить целиком; новые функции выносить в отдельные файлы (как `rules.js`) |
| Upstream-TODO в игровой логике | Код писался под другую версию/режим | `www/gwent.js:190` (`TODO skellige`), `661`, `1265`, `1455`; `www/factions.js:53` (`TODO online`) | Неизвестно, какие ветки недоделаны; `placedEffectsActive` — временное состояние вместо нормального game state | Разобрать по одному при касании соответствующей механики; online-режим вне scope |
| Явный список тестов в `package.json` | Глоб-паттерн ломал CI на разных Node/ОС | `package.json` (`scripts.test`), `docs/ponytail-audit.md:32-33` | Новый тест забывают добавить — он не запускается | Оставить, но добавить тест-«сторож», сверяющий файлы `tests/*.test.mjs` со списком |
| `versionName`/`versionCode` правятся вручную в Gradle, версия дублируется в `package.json` | Нет единого источника версии | `package.json:3`, `android/app/build.gradle:7-8`, `build-apk.sh:6` | Рассинхрон версий APK и пакета | Генерировать `versionName` из `package.json`, `versionCode` — из счётчика/тега |
| `sharp` в devDependencies ради одного скрипта | Импорт русских карт — разовая операция | `package.json` (`devDependencies`), `scripts/import-ru-cards.mjs` | Лишняя зависимость при `npm ci` (нативные бинарники) | Оставить (осознанно, см. `docs/ponytail-audit.md:27-28`) или вынести в отдельный `tools/package.json` |
| `android/` — сгенерированный каркас, но часть файлов правится руками (`AndroidManifest`, `strings.xml`, `build.gradle`) | Capacitor не покрывает нужные настройки | `android/app/src/main/AndroidManifest.xml`, `android/app/src/main/res/values/strings.xml`, `android/app/build.gradle` | `cap sync` не перезаписывает эти файлы, но обновление Capacitor может потребовать ручного merge | Фиксировать ручные правки в README/этой карте при обновлении Capacitor |
