# Контекст для агента

Проект: портретный Android-клиент гвинта из «Ведьмак 3» (Capacitor + ванильный JS).
Не официальный клиент CD PROJEKT RED и не ККИ «Гвинт».

## С чего начинать

1. `README.md` — что это, как собрать, что исправлено.
2. `docs/witcher3-rules.md` — правила, на которые опирается код.
3. `docs/decoy-fix.md` — почему Чучело работает именно так.
4. `SECURITY.md` — модель угрозы и отчёт проверки.
5. `docs/codebase/` — карта проекта: стек, структура, архитектура, соглашения,
   интеграции, тесты, риски. Это снимок: перед доверием сверь `.map-head`
   с `git log -1 --format=%h -- . ':(exclude)docs/codebase'`.

## Правила работы

- **Источник истины по правилам** — `www/rules.js`. Не дублируй проверки Чучела,
  сторон стола и лидеров в других файлах: вызывай `GwentRules`.
- Любая правка поведения = тест в `tests/`. `npm test` должен быть зелёным.
- Правила берём из версии **Ведьмак 3**, а не из отдельной ККИ. Ссылки на вики —
  в `docs/witcher3-rules.md`.
- Пользовательские строки — по-русски, идентификаторы — по-английски.
- `www/` — единственная копия веб-слоя. `android/app/src/main/assets/public/`
  создаётся `npx cap sync android` и в git не входит.
- APK в git не коммитим: его собирает CI (`.github/workflows/android.yml`).
- Новые внешние источники (скрипты, картинки, шрифты) добавлять только вместе с
  правкой CSP в `www/index.html` и тестом в `tests/security.test.mjs`.

## Быстрые команды

```bash
npm ci
npm test
npx cap sync android      # обновить веб-ассеты в android/
./build-apk.sh            # нужен ANDROID_HOME и JDK 17+
```
